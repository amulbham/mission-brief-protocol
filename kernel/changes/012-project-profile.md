# Change 012 — Character-Bounded Project Profile

## Status

IMPLEMENTED AS CANDIDATE · Kernel 1.9 Project delivery extension · activation requires final Kernel 1.9 validation and release merge

## Intent

Provide one clean, self-contained MBP kernel that fits ChatGPT Project Instructions, boots directly in every new Project chat, and uses an attached reference only for supplemental detail.

## Exact Delta

1. Add the `PROJECT` direct-activation profile with an 8,000-character hard ceiling.
2. Add `kernel/modules/13-project-kernel.md` as its registered compact constitutional and operational source.
3. Add `PROJECT_REFERENCE` as a generated, optional, non-activating elaboration compiled from authoritative Kernel Track modules.
4. Preserve FULL and the governed SLIM + GUIDE path unchanged.
5. Require PROJECT to name every registered core component and retain the cognitive laws, boot, capsule, verification, relation, closure, lineage, JIT, DSS, and SOC contracts.
6. Permit task-first startup: PROJECT boots before processing the first task; the literal `boot` trigger receives a one-line readiness terminal.
7. Add character-budget, component-coverage, reference-boundary, boot-state, and stress-path conformance tests.

## Reconciliations

### Axiom 4.7

PROJECT gains authority only through CAP-142-BPC and this recorded candidate change. Its flash registry is present inside the prompt; PROJECT_REFERENCE cannot flash anything.

### Compactness versus authority

PROJECT is not a truncated SLIM bootstrap. It is a separately registered direct interface containing the minimum complete enforcement surface. Detailed definitions remain traceable to the existing authoritative modules and the generated PROJECT_REFERENCE artifact.

### Reference availability

Project knowledge retrieval is not deterministic enough to be a boot prerequisite. PROJECT therefore boots without the reference. When a task requires unavailable elaboration, the runtime defers that detail rather than generating a replacement rule.

### Existing boot profiles

FULL remains the complete portable distribution. SLIM + GUIDE retains its exact digest-bound two-stage behavior. PROJECT introduces no backward change to either path.

## Authority Impact

Adds one direct-activation distribution interface and one non-authoritative reference profile. No inherited cognitive law, capsule field, relation type, verification threshold, component jurisdiction, or active Kernel 1.8 release artifact is removed or weakened.

## Version Effect

Planned Kernel remains `1.9`. Capsule schema remains `v3.11`. Boot profile format becomes `1.1`.
